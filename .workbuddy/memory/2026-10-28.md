## 新增 Excel 命令「标记跨表引用」

- 需求：当前工作簿里，若某单元格被本工作表以外的公式引用，则给它涂独特背景色。
- 实现分层（与既有命令一致：逻辑在 F#，Ribbon 只做薄调用）：
  - 新模块 `ExcelNumericalMethods/CrossSheetRefs.fs`
    - `referencesOf : string -> Ref list` 纯文本解析公式里的「工作表!地址」：支持引号名 `'My Sheet'`（`''` 转义）、3D `Sheet1:Sheet3!A1`、整行/整列 `A:A`/`1:1`；跳过字符串字面量、外部工作簿引用 `[Book1]Sheet1!A1`、`#REF!`。
    - `mark : Workbook -> MarkResult`：按工作表遍历 `Publishing.getFormulaCells`，名称不区分大小写解析目标表，3D 按标签顺序展开；跳过公式所在表自身；目标地址去重后按 50 个一块拼地址串一次性 `Interior.Color`，失败退化为逐格。
    - 标记色常量 `MarkColor = 0x00FF00FF`（洋红，COM 为 BGR 顺序）。
    - `MarkResult = { MarkedAreas; MarkedSheets; MissingSheets; ProtectedSheets }`，结果用状态栏提示。
  - Ribbon：`group6`（工作表）新增按钮 `btnMarkCrossSheetRefs`「标记跨表引用」，处理函数 `BtnMarkCrossSheetRefs_Click`。
- 测试：`ExcelNumericalMethods.Test/CrossSheetRefsTest.fs`（9 个用例覆盖上述解析分支）。顺带把 `SelectionCopyTest` 三条期望文案改为当前实现的「当前工作簿【…】工作表【…】选择：」。
- 踩坑：`readNameBack` 返回值必须与引号分支一致返回「名称首字符下标」（最初返回前一个字符下标，导致 3D 引用漏判）。
- 环境：`dotnet build ExcelVSTO.sln` 无法编译 VSTO/WPF（缺 VS 的 OfficeTools targets、net472 XAML），MSBuild.exe 被安全策略拦截；GUI 工程仍需在 Visual Studio 里构建。

## 重做 Excel 命令「工作表引用」（外部地址中转）

- 需求：把当前工作表公式对外部地址的引用集中到表底 A 列做中转，原公式只引用中转格，不再嵌套外部地址。
- 新模块 `ExcelNumericalMethods/WorksheetRefs.fs`：
  - `referencesOf : string -> RefSpan list`：带**位置**的引用解析（Start/Length/Text/Sheets/IsExternalBook/Address），复用 CrossSheetRefs 的扫描思路但增加 `prefixStart` 回溯（引号名、`[Book]Sheet!`、3D 冒号），地址匹配后做边界检查（排除 `(`、`#`、`$` 等）。
  - 只中转「单格 + 非 3D」的外部引用（区域 `A1:B2`/`A:A`/`1:1`、3D、名称引用中转会改变语义，只统计 `SkippedRefs`）；地址统一绝对化（`A1 -> $A$1`）后作为去重 key。
  - 中转格写法：`=Sheet2!$A$1`，原公式中该引用替换为 `$A$行`（`rewriteFormula` 按位置拼接）。
  - 表尾旧中转区识别 = A 列中「公式整体就是一个外部单格引用」（`isRelayFormula`）的连续行；**先收集、确有新引用才清空重建**，保证重复运行幂等；中转格写入不为 0 失败时才改写原公式。
- Ribbon：`btn_referencesOfWorksheet`「工作表引用」（原有按钮，原注释代码替换），执行期间 `Calculation = xlCalculationManual`，结束恢复并 `Calculate()`。
- 测试：`ExcelNumericalMethods.Test/WorksheetRefsTest.fs` 12 例（解析/位置/绝对化/改写/中转格判定）。全部 61 例通过。
- 注意：VSTO 工程本机仍无法用 dotnet 构建（同上），C# 侧只做人工审阅。

## 修正：区域引用也要中转（`大气与烟气参数!$C$7:$C$9` 漏识别）

- 反馈公式：`=理论空气量(大气与烟气参数!$C$7:$C$9,C14)`（煤质!C19），区域引用被当初「只中转单格」的规则跳过。
- 新规则：**单列竖向区域逐格拆成 A 列连续中转格**，原公式改写为 `$A$起:$A$止`（形状 3×1 不变，不依赖溢出/数组公式，幂等识别仍靠「单格纯外部引用」）。
  - `relayFormulasOf prefix address` → 单格给 1 条；`C7:C9` 逐行给 3 条（起止倒写自动归正）；横向/二维/整行整列返回 None。
  - `relayTargetText rows startRow`：rows=1 → `$A$11`，rows>1 → `$A$11:$A$13`。
  - `MaxBlockRows = 1000` 限制块行数。
- `RelayResult.SkippedTexts` 记录未中转引用原文，状态栏显示前 3 个，避免「没识别出来」的错觉。
- 未中转仍包括：横向/二维区域（单列内保持不了形状）、整行整列、3D、名称引用。
- 测试增至 66 例（新增竖向区域展开、形状拒绝、改写文本、真实公式用例），全通过。

## 改造：区域按左上锚点向右下铺块 + 未中转写提示

- 横向 `A1:C1`、二维 `A1:B2` 不再拒绝：仿 `relayBlockOf` 把区域按**左上单元格为锚点、向右下按原形状**铺成 rows×cols 中转块，公式改写为 `$A$r:$C$r2`。
  - `rectOf`（整行整列返回 None）、`colNameOf`、`blockFits`（MaxBlockRows=1000 / MaxBlockCols=100 / MaxBlockCells=10000）。
  - `relayTargetText rows cols startRow`：1×1 → `$A$11`；n×1 → `$A$11:$A$13`；1×n → `$A$11:$C$11`；m×n → `$A$11:$C$12`。
- 整行整列 / 3D / 超大区域：**不再只报状态栏**，在块尾 A 列逐行写 `【未中转】Sheet2!A:A：整行/整列，范围不确定`；提示行可识别（`isHintText`）、每次重建。
- **幂等策略改为「复用 + 追加」**：旧中转块一律不清（原公式正指向它），按内容（逐格公式全等）`findAnchor` 复用，找不到才在旧块之后追加；只重建提示行。避免原先「清空重建后旧公式指向空区域」的破坏。
- `Formula2.getRaw` 新增：一次 IDispatch 读取整片公式数组（逐格读太慢），读不到退回 A 列逐格。
- 测试 72 例全通过；C# 侧（Ribbon1.cs 状态栏）仍无法本机编译，需 VS 构建。

## 补充：本表无外部依赖时写表尾说明

- 新增 `NoteMark = "【提示】"` 与 `NoRefText = "【提示】没有可中转的外部地址"`。
- `isHintText` 同时识别 `HintMark` 与 `NoteMark` 前缀，旧提示清理/重建逻辑无需改动即可覆盖新说明行。
- `relay` 中 `noExternalRefs = allBlocks=0 && hints=0 && arrayCells=0 && 无旧中转块`，
  为真时把 `NoRefText` 并入 `tailTexts`（未中转提示 + 说明），统一写入与重建。
- 结果新增字段 `NoRefNoticeRow`（写入行，未写为 0）；`HintCount` 仍只统计未中转提示数，避免状态栏误报。
- 幂等：二次运行同一行内容一致时不重写；表里后来出现可中转引用时自动清掉该说明行。
- 测试 73 例全通过（新增「识别无外部依赖说明行」）。

## 改为「一条区域公式 + 动态数组溢出」

- `RelayBlock` 由 `Formulas: string[]`（逐格）改为 `Formula: string`（整块一条区域公式）。
  `relayBlockOf` 生成 `=前缀!$C$7:$C$9`，用 `rectOf` 归一化起止（C9:C7 → $C$7:$C$9），单格仍为 1×1。
- 新增 `relayAnchorShape : string -> (int*int) option`：整体一个外部引用时返回覆盖形状，
  单格 (1,1)、区域 (rows,cols)、整行整列 None。用于扫描旧区与推断溢出占位格。
- 旧区扫描（`anchorCovering`）：A 列溢出占位格公式为空，向上找覆盖该行的区域锚点，整块跳过，
  否则 `oldRelayFrom` 会停在占位格上、把旧区误当用户数据。
- `blockAreaEnd` 按锚点形状累加，不再逐行 +1。
- 新增 `rectFree` / `findFreeRow`：新块落点逐行探测「Rows×Cols 矩形全空或只是旧提示」，
  最多探 2000 行，找不到抛错；保证溢出有地可放，避免 #SPILL!。
- 写盘：先对矩形 `ClearContents`，再 `Formula2.set` 写锚点公式。
- `findAnchor` 改为按锚点公式全等匹配复用（旧区块位置稳定，已改写公式不失效）。
- 测试改为「一条溢出公式」语义，新增 `relayAnchorShape` 用例，74 例全通过。
- 注意：`app.Calculation = xlCalculationManual` 下写入后不会立即溢出，
  C# finally 恢复自动计算并 `Calculate()` 后才铺满；因此不做 SpillRange 校验。

## 修复：多格数组公式被跳过，范围引用漏识别

- 现象：`煤质!C19` = `=理论空气量(大气与烟气参数!$C$7:$C$9,C14)` 未被中转，A 列没有对应中转格。
- 根因：`relay` 里 `cell.CurrentArray.Count > 1` 直接跳过。该处实为 `<f t="array" ref="C19:C21">` 的旧式 CSE 数组，
  整块被跳过，其中的外部区域引用从未进入收集循环。
- 修复：新增 `arrayUnitOf`（写入目标, 是否多格 CSE, 是否左上锚点）。
  - CSE 多格：只处理左上锚点，写入落在整个数组区域；顺序 FormulaArray → 整块 Formula2 → 锚点单格。
  - 动态溢出：`CurrentArray` 返回 null（COM 取值抛异常），按普通格处理，写锚点即可。
  - 非锚点一律跳过（同一条公式，避免重复与「不能更改数组的一部分」）。
- `RelayResult`：去掉 `ArrayFormulaCells`，新增 `ArrayUnits`（只登记真正改写的数组），C# 状态栏同步。
- Excel COM 行为实测（重要，供以后参考）：
  - CSE 数组非锚点 `.Formula` 返回同一条数组公式；`.HasArray` 全为 True；`.CurrentArray` 全为该数组区域。
  - 动态溢出格 `.Formula2` 返回空串、`CurrentArray` 返回 null；往溢出格写公式会把溢出拆掉（所以必须跳过）。
  - `Range("B1:B3").FormulaArray = ...` 可整块改写且保持 HasArray。
- 端到端验证方法（绕开被拦的 VS 构建器拦截面）：临时 `net10.0-windows` 控制台 + Office15 PIA 直接引用 ExcelNumericalMethods，
  用 ProgID "Excel.Application" 创建实例打开工作簿**副本**后调 `WorksheetRefs.relay`。
  结果：6 张表 0 失败；煤质 A35 `=大气与烟气参数!$C$11`、A36 `=大气与烟气参数!$C$7:$C$9`（溢出 A36:A38），
  C19 改为 `=理论空气量($A$36:$A$38,C14)` 且 HasArray=True、CurrentArray=$C$19:$C$21；中转区无 #SPILL!/#REF!。
  临时程序用完即删。

## 新增命令「删除中转单元格」（RelayDelete）
- 新模块 `ExcelNumericalMethods/RelayDelete.fs`（+ `ExcelNumericalMethods.Test/RelayDeleteTest.fs`，11 个用例，全套 85 通过）。
- 核心判据 `isUnitExpression`（上下文无关的一元性）：字面量 / 引用 / 名称 / `FUNC(...)` / 整体括号 / `{...}` 才受理；
  任何顶层运算符（含前置 `-`、`%`、空格交集）一律拒绝——内联到 `=B1*2` 会变成 `=A1+B1*2`。
- `referencesOf` 自建扫描器（WorksheetRefs 那份只认带 `!` 的外部引用，这里必须认出本表裸引用）。
  关键：`A1:B2` 作为**一个** ref 片段（表前缀只补一次 → `Sheet1!A1:B2`）。
- `relationTo`：IsTarget / Encloses / Unrelated；区域引用包含目标 → 阻断（不逐格替换）、3D 含目标表 → 阻断。
- 跨表内联必须补表前缀 `inlineText`：同一段文本搬到别的表，`A39` 会被解释成那张表的 A39。
  同表内联不移动文本，相对/绝对写法无影响（公式文本原地解析，只有复制单元格才会偏移）。
- 先在内存算好全部新公式（超 8192 字符即阻断），全部写成功后才 ClearContents，避免改一半留下断链。
- 端到端（临时 fsi + Excel COM）实测：`C1=SUM(A1:B1)` 被 `D1/E1/第二表!A1` 引用 → 全部内联且值不变
  （10 / 6 / 50），`C1` 清空；`=A1+B1`、`SUM(C3:D3)` 含 C3 两种情形均被阻断且文件未改动。
- 环境限制：VSTO 项目在本机沙箱内无法编译（dotnet CLI 缺 VSTO/WPF targets，VS 的构建器调用被安全策略拦截）；
  C# 侧改动沿用既有模式，仅做静态检查。
